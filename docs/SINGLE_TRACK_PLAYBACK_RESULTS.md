# 第五阶段：限时 VMD 单轨驱动实测

2026-10-12，原神国服 7.1.0，用户指定的已运行客户端，PID 9620。接续 [单骨恢复验证](SINGLE_BONE_ROUNDTRIP_RESULTS.md)。

本轮完成了真实 VMD 解析 → 按时间采样 → 连续回调写入左上臂 → 停止恢复的数值链路。**尚未验证稳定、可见的动作播放。** 实测表明原生动画在绝大多数相邻采样之间覆盖了写入，下一阶段应定位动画更新后的合适执行时点。

## 实现范围

`src/windows/single_track_playback.h` 默认关闭，单独使用 `GIMMD_SINGLE_TRACK_PLAYBACK` 构建开关，与同回调单骨实验互斥。继续要求固定 EXE SHA-256、已核对的 getter/setter 入口字节，以及完整、无歧义的角色骨架。

- 在工作线程读取并解析最多 4096 字节的合成 VMD，游戏回调中只采样已解析的关键帧。接受的唯一轨道是 `left_arm_test`，三个旋转关键帧为 0° → 5° → 0°，帧号 0/30/60，无位置位移。这是显式映射到左上臂的测试轨道，尚不是任意 MMD 骨骼导入或轴向标定。
- 初次完整观察时生成从 AvatarRoot 到左上臂的子索引、名称和 native 身份路径；随后清除所有引擎对象指针。每次执行重新查找根节点、逐层复核身份、名称及父子关系，并检查唯一 active Avatar 与路径 active 状态。角色切换、层级变化或身份不符会停止新动作写入。
- 以原局部四元数后乘 VMD 旋转增量。若下一次读取发现原生动画覆盖了上次请求，就采用新的引擎姿态作为基线，避免在旧动画姿态上叠加。停止时恢复最近一次观察到的引擎基线，而非两秒前的初始待机姿态。
- 写入后复读验证，部分写入异常也进入恢复。恢复只在确认的回调线程执行。工作线程先请求停止并等待完成；恢复未完成时保留清理 Hook，报告未完成并拒绝后续实验导出。恢复 setter 总尝试上限为 8，耗尽后保留失败状态，需要退出客户端解除；不会写入身份不匹配的替代对象。
- 局部恢复以 `2e-5` 的四元数分量误差阈值验证，接受正负等价。父节点和游戏动画会跨回调变化，本阶段没有把世界旋转恢复到两秒前作为成功条件，也未验证整个动画系统状态还原。

## 构建与验证

```powershell
.\scripts\build.ps1 -RuntimeProbe -SingleTrackPlayback -Test -OutputDirectory build-single-track-next
python .\scripts\generate-single-track-fixture.py .\build-single-track-next\single-track.vmd
.\build-single-track-next\gimmd-vmd.exe .\build-single-track-next\single-track.vmd 1
```

生成的合成 VMD 为 407 字节。CMake 对应 `-DGIMMD_RUNTIME_PROBE=ON -DGIMMD_SINGLE_TRACK_PLAYBACK=ON`。实机加载沿用 README 的普通加载器方式；必须使用新的输出目录，不能覆盖已加载的 DLL。同一 DLL 生命周期最多消费一次实验。

本轮通过 657 项核心检查、53 项合成宿主运行时检查、CLI 采样验证和未知 EXE 构建拒绝检查。新增测试覆盖峰值采样、回调节流、停止后禁止写入、原生动画覆盖、部分写入异常、恢复失败与重试上限、身份变化及恢复、inactive/歧义角色、层级重排、真实 VMD 解析与损坏输入拒绝。另通过 8 项绑定预览测试，以及默认只读、原单骨实验的构建回归。
