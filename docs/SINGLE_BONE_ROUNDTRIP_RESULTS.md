原始局部四元数：`[0.229454949, -0.362716824, 0.030566562, 0.902691960]`。

请求及复读四元数：`[0.226280957, -0.364705354, 0.0384427719, 0.902390838]`。

恢复四元数与原始值一致。四元数顺序为 x/y/z/w，接受正负等价；误差阈值为最大分量误差小于 `2e-5`。

这是数值层面的 setter 与同回调恢复验证。写入后立即恢复，没有跨帧保持动作，也未验证可见画面变化、连续播放、LateUpdate 覆盖关系、角色切换恢复或全状态还原。引擎 setter 会触发正常的变换脏标记，不能把姿态恢复解释为所有内存逐字节回滚。

## 局部 setter 依据

离线复核确认：

- 上游相机的世界旋转 setter thunk `0x19cb6730` 转到 `0x1437190` → `0x15c5860`，包含父层级旋转转换。
- 本轮局部旋转包装器为 `0x14371d0`，ABI 为 `void(object, const Quaternion*)`，转到 `0x15c57e0`。
- `0x15c57e0` 不做父级逆旋转，调用 `0x11f9830` 归一化并写入节点局部四元数存储；写入位置与已实测的局部 getter 一致，然后按引擎流程标记变换更新。
- 以上三个入口均加入固定构建 profile。执行前要求完整 EXE SHA-256 一致，且各入口前 32 字节精确匹配。

## 实验与恢复流程

`src/windows/pose_roundtrip.h` 实现实验，默认关闭，只有显式构建 `GIMMD_POSE_ROUNDTRIP` 才允许调用 setter：

1. 要求完整层级、唯一 active Avatar 子树、该子树内唯一左上臂，名称、owner、父关系和旋转关系已验证。
2. 在同一回调内复核角色与骨骼 native 身份，以及两者当前 active 状态，不使用前一帧对象缓存。
3. 重新读取局部和世界原姿态；读取异常或非法四元数时不调用 setter。
4. 将 1° 局部 Z 轴增量后乘原局部四元数，归一化，写入并复读确认发生变化。
5. 进入写入调用后必走恢复，即使 setter 在部分写入后异常，或复读异常。恢复失败至多再尝试一次，验证局部和世界姿态均已恢复。
6. 恢复仍失败时关闭采样、停用自己的 Hook、拒绝后续探测调用，并通过报告及非零返回值暴露失败。

实测后补充了“每个实验 DLL 生命周期最多消费一次实验”的保护。该保护在自建宿主中验证；同 DLL 再次调用探测导出不会重新写入。实测时加载的早期实验构建没有这一后加保护，勿再次调用其导出；它没有持续任务，保留映射至游戏退出。
