# 当前角色的次级骨骼物理实验

状态：2026-11-24 已在纳西妲、芭芭拉的当前出场角色上运行并验证停止恢复。纳西妲的前后分区版经用户确认“还不错”，已接入 GUI 调整；芭芭拉在补齐中央裙链并修正弯曲基准后，《Moonride》1.84 秒的内凹、穿模复测获用户确认“正常了”。开发分支为 `codex/secondary-physics`，默认关闭，不替换本机已交付的表情构建。此验收针对上述测试姿态，不代表所有动作和服装都没有穿模。

### 芭芭拉裙面与末帧保持的后续实验

末帧保持改用不改变时间轴 epoch 的 `hold_end`，并处理停止前最后一段模拟时间；多轮实测末帧没有触发物理重置，保持期间局部姿态误差为零。显式暂停跳转会另做 24 个固定步的静止收敛，然后冻结；普通暂停和自然结束不重置。

封闭裙摆增加横向骨骼连接、相邻三角面碰撞和末端方向联动。芭芭拉识别到六个分支；连同控制裙边方向的虚拟末端共有 18 条横向连接、36 个代理三角面。用户确认裙面联动更自然，但《Moonride》1.84 秒仍穿模并内凹；这些代理面不能代表实际蒙皮表面。

后续诊断确认真实骨骼位置与求解粒子相符（误差低于 0.000001 个世界单位），但实际网格截面在两侧裙骨之间存在明显向内偏移。增加一次性网格诊断：仅对自己创建的 Mesh 副本执行 BakeMesh 和可读性设置，读取完成销毁副本；不替换角色的 sharedMesh。诊断输出保留在忽略的会话目录中。

网格诊断进一步通过可恢复的骨骼平移测量蒙皮权重，扣除子树贡献，选择稀疏的衣物顶点；预测与游戏实际蒙皮在该姿态的最大误差约 0.9 mm。由此发现：前中央多个顶点对原先接管的 24 根裙骨权重为零，模型另有未进入 DynamicBoneArray 的 `SkirtF CF B01–B04` 链。该标定只在显式网格诊断时运行，正常播放不执行标定或逐帧 BakeMesh。

现为缺失的前中央 CF 链补充三个真实粒子和一个虚拟末端，保存、恢复全部四根骨骼。上段参与前侧避让，下段参与七分支裙环、21 条横向连接、42 个三角面，原生数组仍只应用一次。首轮接入后用户反馈明显突起，后续将中央链余量收窄至 1.5 cm，并增加中央与左右两侧之间保留初始拱度的弯曲约束。进一步修正中央链的方向基准：始终使用重置后的初始形状传递父骨骼弯曲，避免把已经内折的积分结果作为下一步基准。用户在同一姿态复测确认“正常了”。此补充只针对实际存在、没有被原生数组接管的单分支 CF 链，不宣称覆盖所有服装骨骼。

## 使用范围

先支持当前出场角色的 `DynamicBoneArray`，复用模型已有的头发/衣物粒子及其原有碰撞体。纳西妲、芭芭拉的已测粒子数组没有原生碰撞体，因此补充随 MMD 身体姿态移动的十三个身体胶囊（包括髋部连接和左右大腿上端），并对裙摆骨骼之间的线段检测碰撞。此实现是次级骨骼物理，并非完整布料网格、自碰撞或身体网格碰撞。`DynamicBoneRigidArray` 暂不模拟，载入演员仍使用原来的固定模式。

```powershell
.\scripts\build-7.2.ps1 -OutputDirectory build-studio-7.2-physics
python .\src\gui\player_gui.py
```

在 GUI 选择 `build-studio-7.2-physics` 构建目录，取消披风/辫子静态稳定，在“角色物理”页开启“当前角色动态物理”，然后开始新的当前角色动作。已经开启静态稳定的会话需要退出后重新连接。开关保存在工程的 `physicsEnabled` 字段中；旧工程默认关闭。

“角色物理”页支持以下参数，并可恢复已验证的默认值：

| 参数 | 前侧默认 | 后侧默认 | 可输入范围 |
| --- | --- | --- | --- |
| 上段最大角度 | 24° | 10° | 0–45° |
| 接触余量 | 1.5 cm | 0.4 cm | 0–5 cm |
| 过渡时间 | 60 ms | 160 ms | 20–1000 ms |

裙形支撑默认 95%，范围 0–100%；0 关闭半径支撑，仍保留模拟和碰撞。侧面裙片根据初始位置在前后设置之间插值。参数不是穿模保证，较大角度/余量会增加撑开幅度，较长过渡会增加避让延迟。

设置保存在工程的 `physicsControls` 字段；旧工程使用默认值。改完后点击“恢复游戏动画”，再重新播放应用，无需重连；暂停继续不重载。GUI 和运行时都验证有限数值、完整格式及范围，无效设置拒绝整组应用。旧构建没有参数能力标记时拒绝伪应用，需要选择新构建重新连接。

本机准备了 `projects/7.2-physics-player.gimmd.json` 供《Moonride》对照测试，工程与素材不纳入 Git。第一轮关闭面部表情以单独观察物理。

## 实现与恢复

当前角色原有 Animator、动态骨骼自动更新和辅助 IK 仍由原来的驱动租约暂停。读取模型树与粒子列表，重新核对每个骨骼、管理组件和碰撞体都属于当前模型；如果物理粒子包含 MMD 正在驱动的身体骨骼，就拒绝启用，保持现有身体覆盖检测。

每批 MMD 姿态与根位移写入后，依次执行经 EXE 指纹和入口字节校验的原生积分、约束、姿态缓存，再处理补充碰撞，最后只执行一次粒子到骨骼的应用。不能在完整 `UpdateDynamicBones` 之后再次调用 `ApplyParticlesToTransforms`：实测第二次应用会累加旋转，即使没有修改粒子，也会产生异常大角度。

模拟时间步为 1/60 秒，由动作时间累积；普通暂停不推进，显式暂停跳转会按上述规则收敛。跳转、循环和过大的时间间隔会重置粒子位置及碰撞历史，单次最多四步。不会重新开启游戏的自动物理更新。保留原有粒子弹性、阻尼、刚度、惯性参数；组件默认参数不能代表各粒子的实际参数。

身体胶囊半径根据身体骨骼比例计算。裙摆、披肩、外套对腿部另加随髋宽变化的接触余量，接触距离以初始姿态为上限，避免直接把贴身衣物撑开。除粒子本身外，还检测布料骨骼段；固定端附近的前 20% 不参与段碰撞。封闭裙环的虚拟末端参与联动碰撞，其他虚拟末端跟随父粒子。八轮长度与接触迭代之后保持骨骼段长度，限制相对参考方向的纠正角度（头发 12°，衣物 45°，封闭裙环连续子段 20°），衣物方向每个模拟步最多变化 10°。这些限制会留下残余穿透，不能当作网格无穿模保证。

针对用户反馈的裙摆贴腿，另为名称含 `Skirt` 的真实粒子记录初始裙形半径，在随身体转动的髋部坐标系中尝试维持至少 95% 的开口半径。它只阻止向内塌陷，允许向外摆动。裙摆与腿接触时沿裙子径向向外避让，避免最近表面投影把粒子推到两腿之间。最终长度与转角约束仍可能抵消部分支撑，因此另记录实际最小半径比。

纳西妲原生裙摆粒子从第二节骨骼开始，第一节 `C21/E21/C11` 未参与模拟。对原生裙摆根的直接父骨骼补充上段避让：仅接受同模型、名称含 `Skirt`、只有一个子骨骼、未被其他物理粒子或 MMD 身体轨道占用的父骨骼。保留固定端位置，通过转动父骨骼移动原生粒子的根，随后只执行一次原生下段更新。上段检测从长度的 5% 处开始，增加的局部姿态与其他物理骨骼一起保存和恢复。

上段先后测试了 45° 和统一 20° 的限制，用户反馈前者撑开过多、后者前侧略不足且后侧翘臀时突变。最终改为上述前后分区默认值，并用固定步长的指数过渡平滑抬起和回落；前侧每步转动上限 4°，后侧 1.5°，中间位置插值。仍保留髋部碰撞覆盖。GUI 的配置在每次开始新动作时读取，运行时报告包含实际设置与各上段骨骼的插值结果。

停止时恢复被物理接管的局部姿态、改写的组件控制字段和参考骨骼，再归还原驱动。对象身份发生变化或恢复失败时保留待恢复状态，不提前启用原 Animator。动态物理与旧的披风/辫子静态稳定互斥。

SDK/EXE 核对记录见 `evidence/genshin-7.2-physics-interfaces.json`。已确认 `ShouldTickMultiThread` 检查组件 enabled，`ApplyParticlesToTransformsByComputeThreadResult` 在实际写回前也检查 enabled。已测会话未发生物理失败；这不是对所有角色和游戏状态的线程安全证明。

## 播放性能修正（2026-11-24）

用户报告低帧率后，普通 GUI 会话 `20261124-215306-d20f32f0` 的物理平均回调为 36.09 ms，网格诊断关闭。此前 1.84 秒视觉测试中长时间暂停会稀释整体平均值，3.21 ms 不能代表持续播放的物理成本。

构建脚本原先只对 MinHook 使用 `/O2`，主 DLL 和内联碰撞代码没有启用编译优化。现在所有 C++ 目标使用 `/O2 /fp:precise`，保留调试符号，并把编译模式写入构建清单。碰撞参数、8 轮求解、补充中央链和恢复逻辑保持原样。

同一游戏进程、芭芭拉、《Moonride》、默认物理参数的顺序 A/B 实测（自然播放到末帧并保持 2 秒）：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 物理平均回调，包含暂停/保持 | 24.63 ms | 1.36 ms |
| 角色播放更新平均耗时，包含物理 | 31.10 ms | 7.84 ms |
| 物理实际播放回调平均耗时，排除初始化/暂停 | 旧版未记录 | 1.69 ms |
| 物理实际播放回调最大耗时 | 旧版未记录 | 3.35 ms |
| 物理每个固定子步的分摊耗时，含校验与写回 | 旧版未记录 | 1.02 ms |

新报告增加 `playingSamples`、`playingSteps`、`playingAverageMs`、`playingMaximumMs`、`playingMsPerStep`，只统计成功、未重置且执行了子步的播放回调。不同回调可能包含多个追赶子步；这些指标不是 GPU 帧耗时或游戏 FPS，也不是隔离所有系统负载的基准。

实测记录：`evidence/genshin-7.2-physics-performance-before.json`、`evidence/genshin-7.2-physics-performance-after.json`。两轮都零物理失败、38 根物理骨骼全部恢复；优化后末帧 85 次采样无重置、姿态误差为零。优化构建通过 792 项核心检查和 271 项运行时检查。GUI 继续选择 `build-studio-7.2-physics`，新连接的会话才会复制并加载优化后的 DLL；已连接会话不会热替换 DLL。
